## 1. Technical Architecture & Need for Chronos

### Q1: Why do we need Chronos if Gemini already has a 1-million+ token context window?
**Answer**: Long context windows allow models to process vast raw text, but they do **not** provide temporal state tracking, outcome feedback loops, or deterministic governance. Dumping 10,000 raw sensor rows into Gemini's context window causes latency spikes, high API costs, attention dilution (the "needle in a haystack" problem), and hallucinated trend calculations. Chronos pre-filters raw data, computes exact moving average deltas, structures state transitions, and enforces SOP safety rules deterministically before Gemini ever sees the prompt.

### Q2: Why not simply use standard RAG (Retrieval-Augmented Generation)?
**Answer**: Standard RAG relies on semantic vector similarity. Vector search is fundamentally **timeless**—it finds text chunks that *look* similar in embedding space, but completely fails at temporal sequence reconstruction. Vector RAG cannot answer: *"Did action X executed 10 minutes ago resolve anomaly Y?"* Chronos uses a bi-temporal property graph (Kùzu) to index explicit temporal causality and state deltas over time.

### Q3: Why not use Google BigQuery alone?
**Answer**: BigQuery is an exceptional relational SQL database for storing raw telemetry rows, but SQL queries do not maintain state graph topologies, decision lineage, or active MCP tool contracts for LLMs. Chronos uses BigQuery as its enterprise raw data layer and builds derived temporal intelligence and graph relationships on top.

### Q4: Why not use a standard vector database (e.g., Pinecone, Chroma)?
**Answer**: Vector databases store high-dimensional embeddings for semantic search, not state graphs or time-indexed causality. A vector DB cannot enforce SOP safety rule constraints or store outcome writebacks linked to past decisions.

### Q5: Why adopt the Model Context Protocol (MCP)?
**Answer**: MCP is an open standard that decouples Gemini's reasoning engine from backend domain context. By exposing `get_context()` and `record_outcome()` over MCP, Chronos can interface seamlessly with Gemini, Claude, or any future agent framework without rewriting integration code.

### Q6: What exactly does Chronos add to Gemini?
**Answer**: Chronos adds **Temporal Memory, Outcome Feedback, Policy Governance, and Grounded Provenance**. It transforms Gemini from a stateless image/text analyzer into an auditable, context-aware industrial decision system.

### Q7: Is Chronos another LLM or custom fine-tuned model?
**Answer**: No. Chronos is strictly **non-generative**. It is a temporal graph and governance context engine written in Python and Kùzu graph DB. Gemini handles all generative language and multimodal perception; Chronos handles context, memory, and rules.

## 2. Reasoning, Provenance & Governance

### Q8: Where does temporal reasoning actually happen?
**Answer**: Temporal reasoning is a collaborative process. Chronos performs **structural temporal retrieval** (calculating sensor deltas, matching past action outcome nodes, fetching SOP rules). Gemini performs **higher-level contextual reasoning** over that structured payload to synthesize the final diagnostic recommendation.

### Q9: How is auditable provenance maintained?
**Answer**: Every decision generated by Gemini is linked to a deterministic evidence quad in Chronos' Kùzu graph: `[Telemetry Timestamp ID, GCS Image ID, Historical Action/Outcome ID, SOP Section ID]`. If an auditor inspects a decision, Chronos can reconstruct the exact state graph that existed at decision time.

### Q10: How does Chronos learn from past outcomes?
**Answer**: Through closed-loop writeback via the `record_outcome()` MCP tool. When a human engineer executes an action (e.g., replacing a bearing) and sensors return to normal, Chronos records an `OutcomeNode` tied to that decision in the graph. Future `get_context()` calls retrieve this positive outcome as precedent.

### Q11: What happens if Gemini generates an incorrect recommendation?
**Answer**: Chronos acts as a safety firewall. Before an action can be presented to an operator or executed, Chronos evaluates it against stored SOP policy constraints (`get_policy()`). If Gemini recommends an action that violates safety thresholds or repeats a failed intervention, Chronos flags the restriction and blocks execution.

### Q12: How do you prevent LLM hallucinations?
**Answer**: 
1. We mandate that Gemini's system prompt strictly restrict claims to evidence present in the `Context Package`.
2. We run an automated evidence parser that verifies every statement cites a valid telemetry ID, image ID, or SOP section.
3. We enforce deterministic policy checks in Chronos before presenting decisions to the user.

## 3. Google Cloud & Scalability

### Q13: Why did you choose Google Cloud tools (Vertex AI, BigQuery, GCS)?
**Answer**: Google Cloud provides an integrated end-to-end enterprise AI stack: Cloud Storage efficiently stores high-resolution industrial photos; BigQuery handles streaming sensor telemetry at scale; Vertex AI offers low-latency access to multimodal Gemini 2.0 models.

### Q14: Why Vertex AI over standard direct API endpoints?
**Answer**: Vertex AI provides enterprise IAM security, model monitoring, regional data compliance, and native integration with Google Cloud Storage artifacts.

### Q15: How does this architecture scale across an entire manufacturing plant?
**Answer**: BigQuery and Cloud Storage auto-scale to petabytes of enterprise data. Chronos' Kùzu embedded graph engine operates with $O(1)$ index lookups per asset ID, enabling real-time context retrieval for thousands of concurrent industrial machines.

### Q16: Is Chronos domain-agnostic?
**Answer**: Yes. While our hackathon demo focuses on industrial predictive maintenance (Pump-07), Chronos' core graph schema (`Entity -> State -> Action -> Outcome -> Policy`) applies equally to healthcare patient monitoring, financial fraud detection, and autonomous fleet management.

## 4. Hackathon MVP & Future Scope

### Q17: What is actually implemented during the 24-hour hackathon?
**Answer**: A complete, functional vertical slice:
1. Pump-07 synthetic telemetry stream in BigQuery + thermal inspection photos in GCS.
2. Chronos MCP server exposing `get_context()`, `get_policy()`, `record_decision()`, and `record_outcome()`.
3. Gemini 2.0 multimodal reasoning pipeline via Vertex AI.
4. Streamlit operational dashboard comparing Baseline Gemini vs. Gemini + Chronos.
5. Automated benchmark suite evaluating 20 temporal scenarios.

### Q18: What is deferred to future work?
**Answer**: Multi-site cross-facility graph federation, direct SAP/Maximo CMMS API sync, fine-tuning Gemini model weights, and real-time video stream optical flow parsing.

### Q19: What happens if the live Google Cloud API fails during judging?
**Answer**: We have built a deterministic, zero-latency demo fallback module (`demo_fallback_mock.py`). If cloud network connectivity drops, the system seamlessly serves pre-cached context packages and verified Gemini decision trails, ensuring zero presentation downtime.

### Q20: What is your team's strongest single differentiator?
**Answer**: **Closed-Loop Outcome Memory with Grounded Governance**. We don't just dump more tokens into an LLM; we give Gemini persistent memory of past actions and their observed success, deterministically governed by real-world SOP rules.
