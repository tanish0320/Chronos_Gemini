## 1. Overview & Data Flow Pipeline

Data in Chronos moves through a four-stage pipeline:

$$\text{Google Cloud Data Layer} \longrightarrow \text{Chronos Temporal Graph} \longrightarrow \text{Context Package} \longrightarrow \text{Gemini Reasoning}$$

```mermaid
flowchart LR
    subgraph Data_Layer ["Google Cloud Data Layer"]
        BQ[("BigQuery Telemetry")]
        GCS[("GCS Image/SOP Storage")]
    end
    
    subgraph Chronos_Layer ["Chronos Graph Layer (Kùzu / SQLite)"]
        NodeEntity["Entity (Pump-07)"]
        NodeState["State Snapshot"]
        NodeEvent["Event (Vibration Anomaly)"]
        NodeAction["Action (ACT-881)"]
        NodeOutcome["Outcome (Cooling Ineffective)"]
        NodeSOP["Policy (MM-PUMP-07 Sec 4.2)"]
    end
    
    subgraph Package_Layer ["Context Package Layer"]
        CP["Context Package JSON"]
    end
    
    subgraph AI_Layer ["Gemini Layer"]
        Gemini["Gemini Reasoning"]
    end

    BQ -->|Telemetry Deltas| NodeState
    GCS -->|Image URIs & SOP Rules| NodeSOP
    NodeEntity --> NodeState
    NodeState --> NodeEvent
    NodeEvent --> NodeAction
    NodeAction --> NodeOutcome
    NodeSOP --> NodeAction
    
    NodeState & NodeEvent & NodeAction & NodeOutcome & NodeSOP --> CP
    CP --> Gemini
```

## 2. Google Cloud Enterprise Data Schemas

### 2.1 BigQuery Sensor Telemetry Table (`chronos_telemetry.sensor_readings`)

```sql
CREATE TABLE `chronos_telemetry.sensor_readings` (
    timestamp TIMESTAMP NOT NULL,
    asset_id STRING NOT NULL,
    temperature_c FLOAT64 NOT NULL,
    vibration_mms FLOAT64 NOT NULL,
    pressure_bar FLOAT64 NOT NULL,
    rpm INT64 NOT NULL,
    anomaly_flag BOOLEAN DEFAULT FALSE,
    ingestion_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP()
)
PARTITION BY DATE(timestamp)
CLUSTER BY asset_id;
```

## 3. Chronos Temporal Graph Data Model (Kùzu Schemas)

### 3.1 Node Schemas

```cypher
// 1. Asset Entity Node
CREATE NODE TABLE Asset (
    id STRING,
    name STRING,
    location STRING,
    asset_type STRING,
    PRIMARY KEY (id)
);

// 2. Temporal State Snapshot Node
CREATE NODE TABLE StateSnapshot (
    id STRING,
    asset_id STRING,
    timestamp TIMESTAMP,
    temperature_c DOUBLE,
    vibration_mms DOUBLE,
    pressure_bar DOUBLE,
    rpm INT64,
    PRIMARY KEY (id)
);

// 3. Operational Action Node
CREATE NODE TABLE ActionNode (
    id STRING,
    action_type STRING,
    parameters STRING,
    timestamp TIMESTAMP,
    executed_by STRING,
    PRIMARY KEY (id)
);

// 4. Action Outcome Node
CREATE NODE TABLE OutcomeNode (
    id STRING,
    action_id STRING,
    temp_delta DOUBLE,
    vibration_delta DOUBLE,
    success BOOLEAN,
    observation STRING,
    PRIMARY KEY (id)
);

// 5. Policy / SOP Node
CREATE NODE TABLE PolicyNode (
    id STRING,
    document_id STRING,
    section STRING,
    rule_condition STRING,
    mandated_action STRING,
    PRIMARY KEY (id)
);
```

### 3.2 Relational Edge Schemas

```cypher
CREATE REL TABLE HAS_STATE(FROM Asset TO StateSnapshot);
CREATE REL TABLE TRIGGERED_ACTION(FROM StateSnapshot TO ActionNode);
CREATE REL TABLE PRODUCED_OUTCOME(FROM ActionNode TO OutcomeNode);
CREATE REL TABLE GOVERNED_BY(FROM ActionNode TO PolicyNode);
```
